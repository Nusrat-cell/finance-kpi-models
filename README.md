# Finance KPI Models

Monthly finance KPIs built from ERP-style exports with layered SQL models in
the dbt style: staging, intermediate and marts, with 28 data tests, a
Power BI star schema and ready-made DAX measures.

The scenario is a company selling scientific lasers worldwide. It invoices
in DKK, EUR, USD and JPY, and its customers pay late, pay in instalments and
sometimes return goods. Finance wants revenue, gross margin, budget variance
and days sales outstanding (DSO) every month, all in DKK.

## Run it

```bash
pip install -r requirements.txt   # only PyYAML, to read schema.yml
python kpi.py build               # load seeds, build 14 models, run 28 tests
python kpi.py export              # marts to exports/*.csv for Power BI
python kpi.py dag                 # show the dependency graph
```

## Model layers

```
seeds (ERP exports)          staging              intermediate              marts
erp_invoice_lines  ->  stg_invoice_lines  -\
fx_monthly_rates   ->  stg_fx_rates       --+-> int_invoice_lines_dkk -+-> fct_invoice_lines
erp_products       ->  stg_products       -/                          +-> fct_receivables
erp_payments       ->  stg_payments  ---------------------------------+-> kpi_monthly
budget_monthly     ->  stg_budget  -----------------------------------+-> kpi_product_line_monthly
erp_customers      ->  stg_customers  --------------------------------+-> dim_customer, dim_product, dim_date
```

- **Staging** renames, casts types and removes duplicates. Nothing else.
- **Intermediate** holds the business logic used by several marts: currency
  conversion at the invoice month's average rate, and cost of goods sold
  from the product's standard cost (kept in EUR, converted to DKK).
- **Marts** are what Power BI reads: a fact table at invoice line grain,
  receivables per invoice, and the monthly KPI tables.

Models reference each other with `{{ ref('model') }}` like dbt, and
`kpi.py` works out the build order from those references. I wrote the small
runner so the project needs no warehouse to try out; the SQL is close to
standard and would move to dbt on Snowflake or DuckDB with few changes.

## KPIs

| KPI | Definition |
|---|---|
| Revenue (DKK) | Invoice lines x month-average FX rate; credit notes are negative |
| Gross margin % | (Revenue minus standard cost) / revenue |
| Budget variance % | (Actual minus budget) / budget, per month and per product line |
| Receivables | Invoiced minus paid, rebuilt at every month end |
| DSO | Receivables at month end / revenue of the month x days in the month |

Sample output (`exports/kpi_monthly.csv`):

| month | revenue_dkk | budget_variance_pct | gross_margin_pct | dso_days |
|---|---|---|---|---|
| 2026-03 | 10,494,410 | 12.0 | 46.9 | 51 |
| 2026-06 | 12,706,578 | 29.9 | 44.6 | 63 |
| 2026-09 | 10,121,124 | -0.7 | 46.4 | 48 |

## Tests

`models/schema.yml` declares tests in dbt's format: `unique`, `not_null`,
`accepted_values` and `relationships` (every invoice line's customer, product
and date must exist in the dimensions). The `tests/` folder holds SQL tests
that pass when they return no rows:

- **Revenue reconciles to source.** The fact table's total must equal the raw
  export converted at the month rate. This catches joins that drop rows (a
  currency with no rate) or multiply them.
- **Instalments are combined.** An invoice paid in two parts appears once,
  as paid. Joining payments straight onto invoice lines would duplicate
  revenue, so payments are summed per invoice first.
- **Receivables are never negative**, and **gross margin stays in 0..90 %**,
  which flags a standard cost entered in the wrong currency.

The seed data contains a duplicated export line, a split payment and a
credit note on purpose. I checked that the tests really catch problems by
switching off the de-duplication in staging: the unique test and the
reconciliation test both failed, as they should.

## Power BI

`exports/` contains the star schema as CSV (`dim_customer`, `dim_product`,
`dim_date`, `fct_invoice_lines`, `fct_receivables`) and
`powerbi/measures.dax` has the measures: revenue, gross margin %, YTD,
same period last year, month on month, credit notes, open and overdue
receivables. CI rebuilds the exports and fails if they are out of date.

## Data

All seed data is invented and generated by `scripts/generate_seeds.py`
(fixed random seed, so it is reproducible). Exchange rates are realistic
month averages, not official rates.
